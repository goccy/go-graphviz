# Design: Upgrade go-graphviz to graphviz 15.1.1

Date: 2026-08-09
Status: Approved (strategy + checkpoint list confirmed by user)

## Goal

Update the vendored Graphviz version in go-graphviz from **12.2.1** to the latest release, **15.1.1**, adapting the Go wrapper and the generated C/WASM binding layer as required. The result must pass the existing test suite and keep the project's public Go API unchanged.

## Background: how the vendoring works

- Graphviz C sources are compiled to a single WebAssembly binary (`internal/wasm/graphviz.wasm`, ~1.5 MB) inside Docker (wasi-sdk 24, binaryen 119, expat 2.6.3), per `internal/wasm/build/Dockerfile`.
- `internal/wasm/build/bind.c` is a generated C shim that exposes the graphviz C API (structs + functions) to the WASM host. It is generated by the internal `nori` tool (`protoc-gen-nori`) from `internal/wasm/bind.proto`, which mirrors the C struct layouts and function signatures in a proto3-like schema.
- `internal/wasm/bind.go` is the Go counterpart (also generated from `bind.proto`): it marshals structs/strings across the WASM boundary via wazero.
- The Go packages `cdt`, `cgraph`, `gvc` call into the WASM exports. The version is tracked in `graphviz.version`; the committed `graphviz.wasm` is what ships.
- CI runs `go test -race ./...` on the committed wasm; it never rebuilds it.

## Strategy: checkpoint stepping

Four checkpoints instead of stepping through all 19 releases after 12.2.1:

```
12.2.1 ──► 13.0.1 ──► 13.1.2 ──► 14.1.5 ──► 15.1.1
```

Rationale (verified against upstream CHANGELOG.md and source tarballs):

- **13.0.0** is the single large API overhaul (~20 breaking changes that touch the bind surface). 13.0.1 = 13.0.0 + fixes, so it is the natural first checkpoint.
- **13.1.x** contains no C API changes (bug fixes only).
- **14.0.0** removes `agcanonStr` (the only API removal in the 14.x line); 14.1.5 is the last 14.x release and its series contains no further API changes.
- **15.0.0** removes the `diffimg` utility (irrelevant — we compile libraries, not utilities); 15.1.x has no API changes.
- Patch releases within a series never change the C API per their changelogs, so stepping through all 19 versions would cost ~4x the rebuild cycles for near-zero extra attribution value.

Each checkpoint lands on `master` as an independently green commit (`graphviz updated to X.Y.Z`), matching the project's existing history style.

## Per-checkpoint workflow

Same loop at each of the 4 checkpoints:

1. **Bump** `graphviz.version` to the checkpoint version.
2. **Reconcile the build surface**: download the version tarball from GitLab generic packages, diff `lib/` structure and the explicitly-listed source files against `internal/wasm/build/Makefile`, and check the Dockerfile's configure flags. Known for 15.1.1 (verified):
   - `lib/vmalloc/` removed → drop `$(GRAPHVIZ_ROOT)/lib/vmalloc/*.c`
   - `lib/neatogen/memory.c` removed → drop the explicit entry
   - `--with-ipsepcola=no` and `--enable-ltdl=no` still accepted by configure; `lib/rbtree/test_red_black_tree.c` still present → Dockerfile unchanged
3. **Fix `bind.proto`** against the real headers of the checkpoint version:
   - Struct layout changes: `Dict_t.data` is now a `Dtdata_t` value instead of `Dtdata_t *`; `Agsym_t` gained `owner`; `Agclos_t.strdict` is now an opaque pointer; `Agiddisc_t.alloc` member removed; `GVJ_t.output_data_allocated`/`output_data_position` are now `size_t`; `GVJ_t.imagedata` is now `unsigned char *`. (`xdot_color_stop.frac` → `double` and `rank_t.cache_nc` → `int64_t` also changed upstream but are **not bound** in `bind.proto`, so no action for them.)
   - Signature changes: `agstrfree` gains an `is_html` parameter; `agconcat` gains a `filename` parameter; `agidsubg` loses the `cflag` parameter; `gvRenderData` takes `size_t *` for length.
   - Removed functions — drop from the proto (verified Go code never calls them): `agcanon` (13.0.0), `agcanonStr` (14.0.0), `agsetfile` (13.0.0), `agreadline` (13.0.0), `agalloc`/`agrealloc`/`agfree` (13.0.0).
   - cdt renames (`struct _dtlink_s` → `struct dtlink_s_`, etc.) do not affect the generated shim: the typedef'd names (`Dtlink_t`, `Dtdisc_t`, `Dt_t`, `Dict_t`, …) are preserved in 15.1.1's `cdt.h`.
4. **Regenerate bindings**: build `nori` (`internal/tools/nori`, buf plugin) and run `buf generate` → fresh `bind.c` + `bind.go`. Compile errors against the new headers are the early-warning net for anything missed in step 3.
5. **Rebuild `graphviz.wasm`** via Docker (`make container/build generate/wasm`) with OrbStack running; commit the new binary.
6. **`go test ./...`** — catches silent struct-layout mismatches (generated marshaling is layout-exact) and semantic regressions; fix in Go/generated code until green.
7. **Commit** the checkpoint (`graphviz.version`, `graphviz.wasm`, regenerated `bind.c`/`bind.go`/`bind.proto` changes, wasm Makefile/Dockerfile changes).

## Verification

- Per checkpoint: `go test ./...` (includes image-hash tests in `compatible_test.go` that compare wasm rendering against the system `dot` — installed system version is 15.1.0, a useful external oracle near the final target).
- Final checkpoint only: full `go test -race ./...` (mirrors CI), `cd cmd/dot && go build`, and a smoke render across all 11 layouts × 4 formats.
- `testdata/imagehash.json`: regenerate only if a hash test actually fails at a checkpoint; prefer doing so at the final checkpoint to avoid churn.

## Risks & contingencies

- **Silent struct-layout mismatches** (proto disagrees with real headers but both sides still compile): caught by tests since marshaling is layout-exact; any escape would surface as parse/render failure, not corruption. If a mismatch escapes, add targeted struct assertions in tests.
- **Docker availability**: OrbStack is installed but stopped; start it before builds. If the Docker build proves flaky, a local wasi-sdk build is a dev-loop fallback, but the Dockerfile stays canonical.
- **Semantic changes in 13.0.x** (string pool text/html distinction, `nop` label handling) may alter rendered output → handled via hash regeneration policy above.
- **Intractable checkpoint**: stop, report, reassess (fallback: direct jump to 15.1.1, or pin to a working intermediate).

## Out of scope

- No public Go API additions or changes.
- No changes to the `nori` generator itself.
- No new layouts/formats.
- No toolchain bumps (wasi-sdk 24, binaryen 119, expat 2.6.3) unless a checkpoint forces them.
